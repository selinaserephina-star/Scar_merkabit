## 1. Scope and method

This audit does **not** certify that the underlying mathematical framework (group-theoretic model of Sp₆(2), 2·Sp₆(2), W(E₈), the D₄ crystal construction, etc.) is a correct or meaningful model of anything beyond itself. It certifies a narrower, checkable claim: **that the numeric results asserted in the registry for these five units are reproduced by independently re-executing the delivered code, from the delivered inputs, in a clean environment.**

Steps taken for each unit:
1. Verified SHA256 of every file in each package against its own `SHA256SUMS.txt` — all files matched (100%).
2. Read the corresponding `verify_*.py` script in full to identify its actual inputs/outputs (not just its docstring claims).
3. Executed the script fresh, with no pre-supplied results, and compared the resulting PASS/FAIL count and every individual check ID against the shipped `.log` file.
4. Where a script depended on cached intermediate data not included in the package (see §2), that dependency was rebuilt from its own source package rather than assumed.

## 2. Dependency reconstruction

None of the five target scripts is self-contained; each reads `.npz`/`.npy` checkpoint files from earlier pipeline stages (Stone U, Stone V, Stone W) that were not included in the individual delivery zips (reasonably — they are internal working state, not addressee-facing artifacts). To get a genuine from-scratch verification rather than a trust-the-log exercise, these were rebuilt directly:

All three rebuilds succeeded cleanly on first attempt with no manual correction.

## 4. Discrepancy flagged

**SM-029:** `REGISTRY_SNAPSHOT_v0.35.md` states "32/32 checks" in two places in its SM-029 entry. Both the shipped `verify_schur_class_pinning.log` and this audit's independent from-scratch re-run agree with each other exactly (same 31 check IDs, same PASS count, same values) but disagree with the registry's stated count. This looks like a bookkeeping slip in the prose summary rather than a computational error — no check is missing or hidden; the artifact is internally consistent, just miscounted in the surrounding text. Recommend the registry entry be corrected to "31/31" (or the source of the extra count identified, if one exists elsewhere).

No other discrepancies were found. No claimed numeric result failed to reproduce.
